## 우선순위 높음 (연동·데이터)
1. **YK-OS `/v1/employee/light` 연동** — 316명의 직위·역임을 채운다. 현재는 홈페이지 게재 순서로 추정한 대표 19·고문 2·파트너 37만 확보.
   **동명이인(이솔·조아라 각 2명) 때문에 이름 기반 모델은 한계가 있다. 사번(employee id) 기준으로 바꿔야 한다.**
2. **`/v1/incident_category` 확인** — 홈페이지 세부 태그(200종) ↔ YK-OS 2단 분류 매핑표 작성. 추천 로직의 기준이 여기서 나온다.
3. **추천 가중치 확정** — `docs/02-결정사항.md`의 표. 특히 "관할기관 근무 이력 40"은 표현 수위와 함께 검토.
4. **예약 정보 연동** — 지금 `app/data/bookings.js` 는 가명 4건이다. 실제로는 YK-OS 콜 탭(`/#/app/visit` → 상담 내용 작성 모달 1콜)에서 읽어와야 한다.
   필드 매핑은 `docs/04-데이터소스.md` 의 콜 탭 표 참조. **`사건개요(영업전략팀)` 이 비면 교차검증 뎁스를 건너뛰는 분기**를 그대로 살릴 것.
5. **콜 메모 요약 생성** — 원문 1,300자를 문장 6개로 줄이는 일. 콜 탭에 이미 있는 **`AI 리포트`** 버튼과 같은 자리에서 만드는 게 자연스럽다. 요약 품질이 교차검증의 전부다.
6. **브랜드 영상 자체 호스팅** — 현재 목업은 `yklawfirm.co.kr/video/main_video.webm`을 직접 참조한다. 태블릿은 오프라인·저대역 상황이 있으므로 파일을 태블릿에 동봉하거나 사내 CDN에 올릴 것. 상담 대기 시간에 맞는 **전용 인트로 영상**(15~30초 루프) 제작도 검토.
7. **고문·전문위원·자문위원 상세** — 현재는 이름 + 경력 라벨만 있다. `/member/advisory/{id}` 상세를 파싱해 실제 경력 본문을 넣을지 결정. 고객이 이름만 보고 무엇을 판단할 수 있는지가 기준.
8. **약정금 사건유형별 n 재검증** — `docs/04-데이터소스.md`의 표. 백분위는 확정, 표본 수는 재집계 필요. 표본이 5건 미만인 유형은 화면에 금액을 띄우지 않는 편이 낫다.
9. **미러링 실구현** — 프로토타입은 같은 페이지 안에서 DOM을 복제해 보여준다. 실제로는 태블릿과 데스크탑이 다른 기기이므로 **세션 채널**(WebSocket 등)이 필요하다. 전달할 상태는 `{현재화면, 열어본 변호사, 관심목록, 교차검증 결과}` 네 가지뿐이라 페이로드는 작다.
10. **확장 질문 시나리오를 YK-OS 분류에 맞추기** — 지금은 홈페이지 명칭 기준이라 `/v1/incident_category` 와 1:1이 아니다.

## 파싱 재현 방법
```bash
# 바인더 텍스트
pdftotext -layout "260623_[법무법인YK] 구성원바인더_법원.pdf" binder.txt

# 인물 사진 (페이지별 세로형 최대 이미지 + smask 알파 합성 후 축소)
pdfimages -f N -l N -png "<pdf>" out/i
# → PIL로 h > w*1.15 이고 면적 최대인 RGB 이미지 선택, 같은 크기의 L 모드 이미지를 마스크로 합성
```
