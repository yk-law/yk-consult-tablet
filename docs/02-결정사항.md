# 02. 결정사항 (결정 로그)

> 새 결정은 아래에 날짜와 함께 append 한다. 이전 결정을 삭제하지 말고 "→ 변경됨"으로 표시한다.

## 기기와 역할 분리 (2026-09-04 확정)
- YK-OS = 상담실장이 **데스크탑**에서 접근하는 환경
- 상담 태블릿 = 고객에게 제공되는 **별도 태블릿 스크린**
- **EMPLOYEE SIDE 화면 = YK-OS 좌측 메뉴의 「상담 태블릿」 메뉴**. 현재 이 메뉴에는 *방문 예정 목록*, *상담 내용 작성*이 있고, **온라인 바인더는 여기에 추가된다.**

| | 상담 태블릿 (고객) | YK-OS (상담실장) |
|---|---|---|
| 대기화면·변호사 탐색·업무사례·후기·영상 | O | |
| 전자서명 | O | 계약서를 밀어 넣음 |
| 상담 기록 작성 | X | O |
| 상담 스케줄 관리 | X (제거) | O |
| 화면 공유 | 받음 | 보냄 |

- 태블릿에 **로그인 없음**. 상담실장이 방문 예정 목록에서 건을 열면 세션이 붙는다.
- **전자서명은 태블릿에 유지** (이전 전제에서 변경됨 → 재확정)
- **태블릿의 상담 스케줄 관리는 제거** (이전 전제에서 변경됨). 기존 상담 태블릿 목업의 상담관리 탭 전체가 사라진다.

## 온라인 바인더 (2026-09-03~04)
- 목적: 실물 바인더 대체. 프로필을 하나의 상품으로 보고 맨파워를 노출한다.
- **처분권자와의 지연 확인을 고객 화면에 노출해도 된다** (2026-09-03 확정). 단 문구는 **사실 서술만** — "언제 어디서 근무했다". 관계 암시 표현 금지.
- 추천 로직: 화면에 **점수는 노출하지 않되 이유는 보여준다** (2026-09-04 변경. 그 전에는 "노출 안 함"이었음).
- **후기는 전체 목록이 기본**, 변호사 프로필에서 클릭하면 해당 변호사 후기로 필터.
- **초기 분야 선택 화면에 분야별 변호사 수는 노출하지 않는다.**
- 태블릿 최초 화면 = **YK 로고 + 홈페이지 상단 배너 영상**, 「상담을 시작할게요」 버튼으로 진입.
- **검색 지원** (2026-09-04). 이름·분야·출신·직위·경력으로 검색. 태블릿 진입 화면과 목록, YK-OS 추천표 모두.
- **승패소율은 만들지 않는다** (2026-09-04). 백업 데이터 확보가 안 되어 있고, YK-OS 종결 유형이 형사 중심이라 민사·가사를 표현하지 못한다.
- **최초 화면은 브랜드 영상부터** (2026-09-04). yklawfirm.co.kr 상단 배너 영상(`/video/main_video.webm`, 포스터 `/image/ykVideoPoster.webp`)을 무음·반복으로 전면 재생하고, 그 위에 YK 로고와 「상담을 시작할게요」 버튼을 올린다. 로컬 HTML·실제 태블릿에서는 재생되고, Claude 아티팩트 뷰어에서는 CSP로 외부 미디어가 차단되어 그라디언트 배경으로 대체된다. **실서비스에서는 영상 파일을 자체 호스팅**할 것.
- **변호사 외 고문·전문위원·자문위원도 노출** (2026-09-04). 태블릿 하단 `전문가` 탭. 고문 28 · 전문위원 61 · 자문위원 9 = **98명**. 전체/고문/전문위원/자문위원 필터. 이름 + 경력 라벨(정부기관 경력, 경찰 경력, 고용노동부 경력, 관세 전문 등)만 노출하고 담당 분야 리스트는 넣지 않는다.
- **디자인 톤: 프리미엄 · 정숙** (2026-09-04). 아이보리 지면(#FBFAF7) + 헤어라인 구분선(#E9E5DC), 딥 버건디 포인트(#6E2739), 골드 라벨(#A98A4B), 잉크 텍스트(#171C24). 제목·숫자는 Noto Serif KR, 본문은 Noto Sans KR. 카드 박스·둥근 모서리·그림자를 걷어내고 여백과 선으로 위계를 만든다. 추천 순위는 `01 / 02 / 03` 세리프 숫자.
- **대기 화면에 예약자 이름으로 인사한다** (2026-09-04). 「안녕하세요 ○○○ 님」 + 방문 일시·상담실·사건 종류 한 줄. 목업의 이름은 전부 가명.
- **「상담을 시작할게요」 다음에 '예약 정보 확인' 뎁스를 둔다** (2026-09-04). 바로 추천 목록으로 가지 않는다. 문구: "예약해주신 정보를 기반으로 미리 추천 리스트를 준비했습니다".
- **예약 확인 화면은 YK-OS 콜 탭을 추종한다** — 유형(개인/기업) · 역할(사건 당사자/사건 위임인/추천인/기타) + 사건 당사자와의 관계 · 사건 종류(2단) · 방문 일시/지사. 필드명과 값 도메인을 임의로 바꾸지 않는다.
- **콜 메모(`사건개요(영업전략팀)`)는 고객이 교차검증할 수준으로 요약해 노출한다** (2026-09-04). 문장 단위 6개 안팎, 각 문장에 「맞아요 / 달라요」. 「달라요」는 즉시 YK-OS에 정정 요청으로 표시되고, 상담실장은 상담 시작 전에 어디가 틀렸는지 안다. 원문 그대로 붙여넣지 않는다.
- **태블릿 대기 화면은 '미연결'이 기본이다** (2026-09-04). YK-OS와 연결되기 전에는 **브랜드 영상 + 공식 로고 + 대표 수치**만 띄우고, 인사도 시작 버튼도 없다. 상담실장이 방문 예정 목록에서 「화면 공유」를 눌러야 비로소 「안녕하세요 ○○○ 님」과 「상담을 시작할게요」가 뜬다.
- **로고는 공식 로고를 쓴다** — `/_next/static/media/brand_logo1.4419cb1a.svg` (698×136, 네이비 #1A2A56 + 그레이 #A6A8AA). 어두운 영상 위에서는 화이트 단색으로 반전해 얹는다. 파일명에 해시가 붙어 있어 배포 때마다 바뀌므로 **실서비스에서는 로고 파일을 태블릿에 동봉**할 것. 로드 실패 시 타이포그래피 워드마크로 폴백한다.
- **YK-OS 상담 태블릿 화면은 좌/우 분할이다** (2026-09-04, 실제 화면 확인). 상단 탭으로 들어가는 구조가 아니라 **한 스크린에서 좌측 방문 예정 목록 · 우측 고객 화면**을 같이 본다. 온라인 바인더는 우측 영역에 들어간다.
- **바인더 연결 전 상태를 명시한다** — 우측은 「고객 화면 미연결」 안내(연결 3단계)만 보이고, 좌측 목록은 그대로 동작한다.
- **방문 예정 목록의 고객명·사건·연락처 검색은 유지한다** (현행 YK-OS 기능).
- **좌/우 역할 확정** (2026-09-04) — 좌측이 **상담실장이 보는 화면**, 우측이 **고객 태블릿 연결 화면**이다. 우측은 고객 태블릿을 그대로 비추는 미러링 영역이지 상담실장용 분석 패널이 아니다. 분석·추천·처분권자 접점은 전부 좌측에 둔다.
- **미러링은 보기 전용** — 상담실장이 우측 미러를 직접 조작해 고객 화면을 넘기지 않는다. 고객 화면 전환은 좌측 추천 순위표의 「화면 공유」로만 한다.
- **공유 해제 기능** (2026-09-04) — 세 곳(카드 버튼·좌측 연결 배너·우측 고객화면 탭)에서 해제할 수 있다. 해제하면 태블릿은 대기 화면으로 돌아가고 관심 변호사·검색어가 초기화된다. 다음 고객을 앉히기 전에 이전 고객 정보가 남지 않게 하는 것이 목적.
- **나란히 보기도 좌측이 상담실장** (2026-09-04). YK-OS 내부의 좌/우 규칙과 순서를 맞춘다. 좌 = 상담실장 YK-OS, 우 = 고객 태블릿.
- **교차검증은 실시간으로 상담실장 화면에 호출된다** (2026-09-04). 고객이 「맞아요/달라요」를 누르는 즉시 YK-OS의 해당 문장이 강조되고(2.4초 하이라이트), 헤더에 「고객 확인 중」 표시가 점멸하며, 상단 상태가 `고객 정정 요청 N건`으로 바뀐다. 상담실장은 자리에 앉기 전에 어디가 틀렸는지 안다.
- **교차검증이 불가능한 케이스를 별도로 다룬다** (2026-09-04). 콜 단계에서 "내방해서 직접 설명하겠다"며 사건 내용을 말하지 않는 고객이 있다. 이 경우:
  - YK-OS: **「고객 사전 교차검증 내용 없음」** + 사유를 띄운다. 사실관계를 상담에서 처음부터 들어야 한다는 안내를 붙인다.
  - 고객 태블릿: **교차검증 뎁스를 아예 주지 않는다.** 예약 카드(유형·역할·사건 종류)만 남기고 문구도 "사건 이야기는 상담 때 편하게 말씀해 주세요"로 바꾼다. 확인할 게 없는데 확인 화면을 띄우면 안 된다.
  - 판정 기준은 `BOOKINGS[].memo` 가 비어 있는지 여부. 사유는 `memoNote`.
- **확장 질문 시나리오** (2026-09-04). 사건 종류별로 파생될 수 있는 건과 그것을 확인하는 질문을 상담실장 화면에 띄운다. 예) 이혼 → 양육권·양육비 / 재산분할 / 상간소송 / 면접교섭 / 재산명시·은닉.
- **「상담 내용 작성」은 실제로 동작해야 한다** (2026-09-04). 목록의 버튼을 누르면 현행 YK-OS 모달(`[고객명(역할) - 사건종류] 상담 정보`, 탭 1콜~6종료)이 뜬다. 바인더는 **콜 탭만** 바꾸고 나머지 흐름은 손대지 않는다.
- **바인더 결과가 상담 기록으로 자동 이월된다** — 콜 메모·고객 정정·고객 관심 변호사·약정금 가이드가 각각 사건개요/정정박스/부서 배당 의견/제안 금액 칸에 채워진 상태로 열린다. 상담실장이 바인더에서 본 것을 다시 타이핑하지 않는 것이 이 기능의 목적.
- **위임 사무는 자동으로 채우지 않는다** (2026-09-04). 상담실장이 직접 적을 값이다. 확장 질문 시나리오는 좌측 참고 패널에만 남기고 폼에는 넣지 않는다.
- **예약 확인 이후 경로를 분기한다** (2026-09-04). 「확인함」과 「나중에」가 같은 화면으로 가면 확인 버튼의 의미가 없다.
  - 확인함 → **추천 목록**. 사건이 확정됐으니 추천 3인을 앞세운다.
  - 나중에 → **둘러보기**. 추천은 맨 아래 「참고 추천」으로 내리고 정확도가 낮을 수 있다고 밝힌다. 대신 검색·업무사례·후기·전문가를 앞에 둔다. 상단 배너로 언제든 확인 화면으로 되돌아갈 수 있다.
  - 하단 `변호사` 탭도 고객이 있는 경로를 따라간다. 상담실장 화면에는 고객이 어느 쪽을 택했는지 표시된다 — 확인을 미뤘다는 것 자체가 상담에서 알아야 할 신호다.
  - **YK-OS 전용. 고객 태블릿에는 노출하지 않는다** — 고객에게 사건을 늘려 파는 것으로 보이면 안 된다.
  - 각 항목에 「물어보기 → 확인함」 토글. 확인한 항목은 상담 기록의 **위임 사무**에 반영한다.
  - 데이터는 `app/data/scenarios.js`. 키는 사건 종류 소분류 우선, 없으면 대분류 폴백.
  - **실제로 존재하는 건만 담는다** — 없는 사건을 만들어 붙이는 용도가 아니다. 내방 대비 선임율을 올리는 것이 목적이지 건수를 부풀리는 것이 목적이 아니다.
- **여러 예약자 중에서 골라 화면 공유한다** — 목록의 어느 행이든 「화면 공유」를 누르면 그 예약으로 태블릿이 갈아끼워진다. 추천 로직·비용 기준도 그 예약의 사건 종류를 따라 바뀐다.
- **대기 화면 카운터는 검증된 수치만 쓴다** — 변호사 318 · 고문·위원 98 · 전국 사무소 31. 근거를 찾지 못한 「업무사례 1,839」는 제거했다(`docs/04` 참조).

## 방문 예정 목록 기간 필터 (2026-09-08)
- 날짜 `‹ 오늘 ›` 이동을 **오늘 / 내일 / 이번주 / 다음주** 버튼으로 바꾼다. 기본값은 오늘.
- **이번주·다음주는 월요일 시작**(일요일이 주의 마지막). 시연 기준일은 YK-OS 시계와 같은 `2026-09-04`.

## 스택 교체: React + FastAPI (2026-09-16)
- 기존 vanilla HTML/CSS/JS 프로토타입을 **대체**한다. 화면 구조·추천 가중치·기기 분리 전제는 그대로다.
